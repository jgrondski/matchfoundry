Step ER.8: Put every event-day action on the shared loading pattern

Convert the judge, qualifier, review-queue and admin actions to useAction: the clicked button shows a spinner and loading text, everything else waits, and a hung request ends after 10 seconds with a banner.

Executor: any model. Prerequisites: ER.4, ER.6, ER.7. Read first: index.html “Rules for every executor”, ER.7's “Rules this step establishes”, docs/TESTING_STRATEGY.md.

The conversion pattern (apply it to every row below)

// Before
const [isSaving, setIsSaving] = useState(false);
const handleSave = async () => {
  setIsSaving(true);
  try { await doThing(); onClose(); } finally { setIsSaving(false); }
};
<Button disabled={isSaving} onClick={handleSave}>{isSaving ? 'Saving...' : 'Save'}</Button>

// After
const save = useAction(async () => {
  const result = await doThing();
  if (result) onClose(); // store methods return null on failure and report it to the banner themselves
});
<Button loading={save.busy} loadingText="Saving…" onClick={() => void save.run()}>Save</Button>
  1. Delete the local flag (isSaving, isSubmitting, isTogglingTest) and its setters. Overlays that took busy={flag} take busy={action.busy} (combine several with ||).
  2. Keep every validation, early return and post-success step the handler has today, in the same order, inside the action function.
  3. Store methods that return null/false/{ success: false } on failure: treat that as failure (do not close or show success). The store already puts the error in the banner. When a method returns { error } shown inline today (for example unlockBrackets), keep showing it inline.
  4. Never wrap a store call in a second error banner: do not call showError when the store already set apiError.
  5. Loading text: “Saving…”, “Deleting…”, “Verifying…”, “Discarding…”, “Resolving…”, “Unlocking…”, “Seeding…”, “Simulating…”, “Opening…”/“Closing…” as listed below. Use the single-character ellipsis ….
  6. Replace window.confirm only where the row says so; otherwise leave it.

Use installApiMocks, ADMIN_SESSION and FIXTURE_SLUG from e2e/visual/mockApi.ts and the prepare/settle/openDirtyScoreDrawer approach from e2e/overlays.spec.ts (copy the helpers; do not import from another spec). Register the overriding page.route after installApiMocks so it takes precedence.

  1. Loading state: route **/api/tournaments/*/tiers/*/matches/*/score to wait 1 s then fulfill with the fixture tournament. Open the score drawer, type a score, click save. While waiting: the save button shows “Saving…” and button-spinner, and the drawer's Cancel button is disabled. After: the drawer closes.
  2. Timeout: await page.clock.install({ time: FIXED_TIME }) before navigating. Route the score endpoint to never respond. Click save, then await page.clock.runFor(10_500). The feedback-banner shows the timeout message, the save button shows its normal label again and is enabled, the drawer is still open with the typed score.
  3. Error: route the score endpoint to 500 with { error: 'Database unavailable' }. After save: the banner shows “Database unavailable”, the drawer stays open with the typed score.
  4. Conflict: route the score endpoint to 409 with { error: MATCH_CONFLICT_MESSAGE, code: 'MATCH_CONFLICT' } (import the constant from src/features/bracket/matchConflict.ts). After save: match-conflict-notice is visible, the drawer stays open, the banner is not shown.

If the fixture's route for the score endpoint differs from the glob above, use the URL the app actually calls (see saveMatchScores in store.tsx) and record it.
