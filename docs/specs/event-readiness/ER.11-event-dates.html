Specs / Event readiness / ER.11

Step ER.11: Real event dates (start and end)

Replace the free-text tournament date with a validated startDate and optional endDate (both YYYY-MM-DD), stored in two new date columns, entered with date pickers, and shown as formatted text such as “Nov 14–16, 2026”.

Executor: any model. Prerequisite: ER.9 merged. Can run alongside ER.6: the only shared file is src/server/api.ts, where this step edits exactly two places (section C). Run before ER.12, which reads the new columns. Read first: index.html “Rules for every executor”, docs/TESTING_STRATEGY.md.

Why

The event date is a free-text field (placeholder “e.g. March 21-22, 2026”). Stored values include 2026-10-18, Upcoming, Yah and empty strings. Nothing can sort, filter or schedule by it, and ER.12 needs real dates to keep the API warm on event days. Multi-day events are common, so one field is not enough.

Validation happens in the app (validateEventDates). The Postgres date type is a second guard only: it rejects impossible dates such as 2026-02-30, but it accepts loose text such as March 21-22.

Behavior after this step

  • Create Tournament and Settings show Start Date and End Date date pickers instead of the “Event Date” text box. Both are optional. End Date cannot be before Start Date, and cannot be set without a Start Date; the form shows the error under End Date and does not save.
  • Tournament cards show “Nov 14, 2026”, “Nov 14–16, 2026”, “Nov 30 – Dec 2, 2026”, “Dec 30, 2026 – Jan 2, 2027”, or “Date TBD” when no start date is set.
  • The API rejects an invalid date or range with HTTP 400 and the validation message. A save that omits startDate and endDate (for example an old browser tab) keeps the stored dates. Sending '' clears a date.
  • An end date equal to the start date is stored as no end date (a single-day event).
  • Existing free-text dates are not converted. Those tournaments show “Date TBD” until an admin sets the dates in Settings.

A. Shared helpers: create src/features/tournament/eventDates.ts

const ISO_DATE = /^\d{4}-\d{2}-\d{2}$/;

/** True for a real calendar date written YYYY-MM-DD (rejects 2026-02-30 and loose text). */
export function isIsoDate(value: string): boolean {
  if (!ISO_DATE.test(value)) return false;
  const d = new Date(`${value}T00:00:00Z`);
  return !Number.isNaN(d.getTime()) && d.toISOString().slice(0, 10) === value;
}

/** The validation message for an event date range, or null when valid. Empty strings mean "not set". */
export function validateEventDates(startDate: string, endDate: string): string | null {
  if (startDate && !isIsoDate(startDate)) return 'Start date must be a real date (YYYY-MM-DD).';
  if (endDate && !isIsoDate(endDate)) return 'End date must be a real date (YYYY-MM-DD).';
  if (endDate && !startDate) return 'Set a start date before an end date.';
  if (startDate && endDate && endDate < startDate) return 'End date cannot be before the start date.';
  return null;
}

const MONTH_DAY: Intl.DateTimeFormatOptions = { month: 'short', day: 'numeric', timeZone: 'UTC' };
const FULL: Intl.DateTimeFormatOptions = { month: 'short', day: 'numeric', year: 'numeric', timeZone: 'UTC' };
const format = (iso: string, options: Intl.DateTimeFormatOptions) =>
  new Intl.DateTimeFormat('en-US', options).format(new Date(`${iso}T00:00:00Z`));

/**
 * Display text for an event's dates: "Nov 14, 2026", "Nov 14–16, 2026", "Nov 30 – Dec 2, 2026",
 * "Dec 30, 2026 – Jan 2, 2027", or "Date TBD" when there is no valid start date.
 * Dates are calendar days with no time zone, so they are formatted in UTC to avoid shifting a day.
 */
export function formatEventDates(startDate?: string | null, endDate?: string | null): string {
  if (!startDate || !isIsoDate(startDate)) return 'Date TBD';
  if (!endDate || !isIsoDate(endDate) || endDate <= startDate) return format(startDate, FULL);
  if (startDate.slice(0, 4) !== endDate.slice(0, 4)) return `${format(startDate, FULL)} – ${format(endDate, FULL)}`;
  if (startDate.slice(5, 7) !== endDate.slice(5, 7)) return `${format(startDate, MONTH_DAY)} – ${format(endDate, FULL)}`;
  return `${format(startDate, MONTH_DAY)}–${Number(endDate.slice(8, 10))}, ${endDate.slice(0, 4)}`;
}

The dashes are typed characters: “–” (U+2013 en dash). In the same-month form there are no spaces around it; in the other two forms there is one space on each side.
