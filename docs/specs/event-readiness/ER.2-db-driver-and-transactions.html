Step ER.2: Pooled Neon driver, transactions, parallel reads

Replace Neon's one-HTTPS-request-per-query driver with its WebSocket pool, add a transaction helper that every existing getDb() call joins automatically, and load a tournament with parallel queries.

Executor: any model. Prerequisite: ER.1. Run before ER.3. Read first: index.html “Rules for every executor”, docs/TESTING_STRATEGY.md, CLAUDE.md section 1 (database port).

Why

src/db/index.ts uses drizzle-orm/neon-http: every query is its own HTTPS request, and the code awaits them one after another, so a write costs 25–40 round trips. That driver also cannot hold a transaction open, so a save that fails halfway leaves partial data. The WebSocket Pool from @neondatabase/serverless keeps a connection open and supports real transactions.

Behavior after this step: identical API responses. Faster requests in production. withTransaction exists but nothing calls it yet (ER.3 does).

B. Transaction context

src/db/txContext.ts (new)

import { AsyncLocalStorage } from 'node:async_hooks';

// The drizzle transaction the current async call chain is running inside, if any.
const storage = new AsyncLocalStorage<unknown>();

export function getActiveTransaction(): unknown | null {
  return storage.getStore() ?? null;
}

export function runInTransactionContext<T>(tx: unknown, fn: () => Promise<T>): Promise<T> {
  return storage.run(tx, fn);
}

src/db/transaction.ts (new)

import { getBaseDb } from './index';
import { getActiveTransaction, runInTransactionContext } from './txContext';

/**
 * Runs fn inside one database transaction. Every getDb() call made by fn (directly or through any
 * function it calls) uses that transaction. A throw rolls everything back. Nested calls join the
 * outer transaction.
 */
export async function withTransaction<T>(fn: () => Promise<T>): Promise<T> {
  if (getActiveTransaction()) return fn();
  return getBaseDb().transaction((tx: unknown) => runInTransactionContext(tx, fn));
}

C. src/db/index.ts (replace the file)

import { drizzle as drizzleNeon } from 'drizzle-orm/neon-serverless';
import { drizzle as drizzlePg } from 'drizzle-orm/node-postgres';
import { Pool as NeonPool, neonConfig } from '@neondatabase/serverless';
import { attachDatabasePool } from '@vercel/functions';
import ws from 'ws';
import pg from 'pg';
import * as schema from './schema';
import { queryCounterLogger } from '../server/requestMetrics';
import { getActiveTransaction } from './txContext';

let pgPool: pg.Pool | null = null;
let neonPool: NeonPool | null = null;
let currentDbInstance: any = null;

export { assertDatabaseConfig } from './config';
import { assertDatabaseConfig } from './config';

export function setDb(dbInstance: any) {
  currentDbInstance = dbInstance;
}

/** The database handle: the active transaction when inside withTransaction, else the shared instance. */
export function getDb(connectionString?: string) {
  const tx = getActiveTransaction();
  if (tx) return tx as any;
  return getBaseDb(connectionString);
}

/** The shared (non-transaction) instance. Only src/db/transaction.ts should call this directly. */
export function getBaseDb(connectionString?: string) {
  if (currentDbInstance) {
    return currentDbInstance;
  }

  const url = connectionString || assertDatabaseConfig();

  if (url.includes('neon.tech')) {
    neonConfig.webSocketConstructor = ws;
    neonPool = new NeonPool({ connectionString: url, max: 5, idleTimeoutMillis: 10_000 });
    neonPool.on('error', err => console.error('[DB] Idle Neon connection error:', err));
    if (process.env.VERCEL) {
      // Keeps the function instance alive long enough to close idle connections cleanly.
      attachDatabasePool(neonPool as unknown as Parameters<typeof attachDatabasePool>[0]);
    }
    currentDbInstance = drizzleNeon({ client: neonPool, schema, logger: queryCounterLogger });
    return currentDbInstance;
  }

  if (!pgPool) {
    pgPool = new pg.Pool({ connectionString: url });
  }
  currentDbInstance = drizzlePg(pgPool, { schema, logger: queryCounterLogger });
  return currentDbInstance;
}

export * from './schema';

E. Real-Postgres tests

pg-mem accepts BEGIN/COMMIT/ROLLBACK and FOR UPDATE but does not roll back and does not block (verified while writing this spec). Rollback and locking are proven only against the local Docker database, in files named *.pg.test.ts that run only under npm run test:pg.

src/db/__tests__/pgTestDb.ts (new; not a test file)

import pg from 'pg';
import { drizzle } from 'drizzle-orm/node-postgres';
import * as schema from '../schema';

/** True only under `npm run test:pg` (npm sets npm_lifecycle_event on every platform). */
export const RUN_PG_TESTS = process.env.npm_lifecycle_event === 'test:pg';

/** Connects to the local Docker database from .env. Refuses any cloud (Neon) URL. */
export function connectLocalPostgres() {
  if (!process.env.DATABASE_URL) {
    try {
      process.loadEnvFile();
    } catch {
      // no .env; fall through to the check below
    }
  }
  const url = process.env.DATABASE_URL;
  if (!url) throw new Error('DATABASE_URL is not set; npm run test:pg needs the local Docker database.');
  if (url.includes('neon.tech')) throw new Error('npm run test:pg must never run against Neon.');
  const pool = new pg.Pool({ connectionString: url });
  return { db: drizzle(pool, { schema }), pool };
}

src/db/__tests__/transactions.pg.test.ts (new)

Wrap everything in describe.skipIf(!RUN_PG_TESTS)('withTransaction on real PostgreSQL', ...). beforeAll: connectLocalPostgres(), setDb(db). afterAll: delete players whose name starts with PGT_, setDb(null), pool.end(). Every name uses the prefix PGT_ plus crypto.randomUUID().

  1. Rollback: inside withTransaction, insert a player through getDb(), then throw. Afterwards the player does not exist.
  2. Commit: inside withTransaction, insert a player; afterwards it exists.
  3. Nested join: an inner withTransaction inserts a player, the outer one throws after it returns; the player does not exist.
  4. Lock blocks: insert a player. Start transaction A: select ... for('update') on that row, then wait 300 ms, then update its notes to 'A'. 50 ms after A starts, start transaction B: select ... for('update') on the same row, record Date.now() when the select returns, update notes to 'B'. Assert B's select returned after A committed (B's timestamp minus A's start is at least 250 ms) and the final notes is 'B'.
