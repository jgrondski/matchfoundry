Specs / Event readiness / ER.4

Step ER.4: Match writes touch only their own rows, and catch same-match edits

Score, forfeit and best-of changes stop deleting and re-inserting every match and game in the tournament; each match carries a revision so a judge saving over someone else's newer scores gets a clear “updated by someone else” message instead of silently overwriting them.

Executor: any model. Prerequisite: ER.3. Run before ER.8 (both edit MatchScoreDrawer.tsx). Read first: index.html “Rules for every executor”, docs/TESTING_STRATEGY.md (cover every bracket format the change touches), CLAUDE.md section 4.

Background: where match data lives

  • Bracket shape and slot assignments (who plays in which slot, who advanced): JSON in bracket_tiers.metadata.bracket (rounds and matchesById).
  • Results: one matches row per bracket match (players, winner, loser, best-of, complete, forfeit) and one games row per recorded game. On read these override the JSON.
  • A third copy of each result, including hasTiebreaker, in tournaments.metadata.matchScores.

Today PUT .../matches/:matchId/score, POST .../forfeit and PUT .../best-of call saveFullTournament, which deletes every matches row of every tier (cascading every games row) and inserts them all again.

src/features/bracket/drawerSync.ts (new)

/**
 * Whether the score drawer should replace its editable games with the latest stored ones.
 * It never discards a judge's unsaved typing because of a background refresh; the save's
 * revision check catches real conflicts instead.
 */
export function shouldResyncDrawer(input: {
  lastSyncedMatchId: string | null; // match id at the last resync, null if never synced
  lastSyncedGamesJson: string | null; // JSON of the games at the last resync
  currentGamesJson: string; // JSON of the games the judge sees now
  matchId: string;
}): boolean {
  if (input.lastSyncedMatchId !== input.matchId) return true;
  return input.currentGamesJson === input.lastSyncedGamesJson;
}

F. Tests

src/api/__tests__/targetedMatchWrites.test.ts

Build locked tournaments with the fixture from relationalIntegrity.test.ts section 4, once per bracket format: Single Elimination Traditional, Double Elimination Traditional, Double Elimination Flat Staged, Double Elimination Accelerated Hybrid (the tier configs are in that file's section 1). For each format:

  1. No mass rewrite: record every matches row's createdAt for the tier. Score round-1 match 1 (Best-of win for player 1). Every row's createdAt is unchanged and the row count is unchanged.
  2. Advancement persisted: the match that bracket routes the winner to has player 1 in the routed slot, both in GET and in its matches row (player1Id or player2Id). For double elimination, the loser appears in the routed losers-bracket slot.
  3. Other games untouched: score match 2, then re-score match 1 with different points. Match 2's games rows are unchanged (same ids).
  4. Retract: re-scoring match 1 so nobody has won yet clears the winner from the next match's slot (GET and row).

Once (Single Elimination only):

  1. First score with no expectedRevision → 200, record revision === 1. Score with expectedRevision: 0 → 409, body { error: MATCH_CONFLICT_MESSAGE, code: 'MATCH_CONFLICT' }, and nothing changed. Score with expectedRevision: 1 → 200 and revision === 2.
  2. Forfeit and best-of each raise the revision by 1.
  3. hasTiebreaker sent with a score is stored in tournaments.metadata.matchScores.
