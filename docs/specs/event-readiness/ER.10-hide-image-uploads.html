Specs / Event readiness / ER.10

Step ER.10: Remove image uploads and image URL fields

Remove every control that sets a player avatar, an organization logo or banner, or a tournament logo or banner. Images that are already saved keep displaying. The proper image feature (object storage) is in the implementation-plan backlog.

Executor: any model. Prerequisite: none. Can run in parallel with ER.9 (no shared files). Read first: index.html “Rules for every executor”, docs/TESTING_STRATEGY.md.

Why

Images are stored in the database as base64 data URLs. Player avatars are sent with every player list and embedded in every tournament payload; organization logos and banners are stored unresized and can be megabytes per row. The feature is unused and unfinished, so it is removed from the UI before the event instead of being fixed now.

Behavior after this step

  • The player add/edit modal has no “Upload Photo” or “Change Photo” button. “Reset to Flag” still appears for a player who already has a custom avatar, so an admin can remove it.
  • Creating or editing an organization shows no logo or banner fields (neither the URL text box nor “Browse”). Saving an existing organization keeps its current logo and banner unchanged.
  • Tournament settings show no “Tournament Logo URL” or “Tournament Banner URL” fields. Saving settings keeps any existing values unchanged.
  • Everywhere images are displayed (avatars, org banners and logos), saved images still display. No data is deleted and no schema changes.
