Step QR.2: Save, verify, unverify, and provisional brackets

Separate saving a qual from verifying it, lock verified quals until they are unverified, show submission date and time, seed unverified quals into draft brackets, simulate unverified quals, and drop walk-in wording.

Executor: any model. Prerequisite: QR.1 complete (every qual is a qualifier_runs row, and session summaries carry runId, submittedAt, verifiedBy, verifiedAt). Read first: index.html “Rules for every executor” and docs/TESTING_STRATEGY.md.

Decisions (already made by the user)

TopicDecision
Save vs verifyEditing scores and notes is a Save that never changes review status. Verify is a separate button and is disabled while there are unsaved edits.
Verified lockA verified qual is frozen everywhere (scores, attempts, notes, DNQ, DQ, reassignment, roster removal). The only action is Unverify, which returns it to Pending.
Zero scoresThe Review dialog may remove every game. A qual with no scores stays on the Review page.
Provisional bracketsUnverified (Pending) quals with at least one score are seeded into draft brackets. DNQ, DQ and quals with no scores are not.
Locking with pending qualsAllowed. The lock confirmation warns with counts.
Walk-insRemove every “walk-in” label and wording. Keep the internal PROVISIONAL_NEW flag and the Discard clean-up of a player the run created.
SimulationSimulated quals are created Pending (SUBMITTED), never pre-verified.

A. Server: adjudication actions and the verified lock

  1. In qualifiers.ts export class QualLockedError extends Error {} and a private assertRunEditable(run) that throws new QualLockedError('This qual is verified. Unverify it before making changes.') when run.status === 'VERIFIED'.
  2. The adjudicate action union becomes 'SAVE' | 'VERIFY' | 'UNVERIFY' | 'DNQ' | 'DQ' | 'CONFIRM_IDENTITY' | 'REASSIGN_PLAYER' | 'PROMOTE_PROVISIONAL' | 'CREATE_NEW_PLAYER'. Delete EDIT_AND_VERIFY and its branch.
  3. SAVE (input: scores, judgeNotes):
    • If the run is IN_PROGRESS, throw "This run hasn't been submitted yet." Then assertRunEditable(run).
    • next = validateQualScores(input.scores, { requireOne: false }) (an empty array is valid).
    • prev = current scores ascending by createdAt. If prev and next differ in length or any position: replaceRunScores(run, next, run.submittedAt ?? now) and audit = `[SCORES EDITED BY ${judgeBy}]: ${prev.join(', ') || 'none'} -> ${next.join(', ') || 'none'}`.
    • base = input.judgeNotes !== undefined ? (input.judgeNotes.trim() || null) : run.judgeNotes. Store audit ? (base ? `${base}\n${audit}` : audit) : base as judgeNotes.
    • Status, source, verifier fields and tournament_players are not touched.
  4. VERIFY: IN_PROGRESS → throw "This run hasn't been submitted yet."; already VERIFIED → return the current summary unchanged; otherwise today's behavior (on the run). Scores are never changed by VERIFY.
  5. UNVERIFY: if the run is not VERIFIED, throw 'Only a verified qual can be unverified.' Otherwise set status 'SUBMITTED', verifiedBy null, verifiedAt null, append `[UNVERIFIED BY ${judgeBy}]` to judgeNotes (newline-separated, same pattern as DNQ), and set tournament_players.qualsCompleted = false for the player.
  6. Call assertRunEditable(run) at the start of: DNQ, DQ, REASSIGN_PLAYER, CREATE_NEW_PLAYER; recordScore (in-person score entry and batch); setTournamentPlayerDisqualification when isDisqualified is true and the player has a run. CONFIRM_IDENTITY and PROMOTE_PROVISIONAL stay allowed (they edit the player profile, not the qual).
  7. src/server/api.ts:
    • In the outer catch near the end of the middleware (the one that returns 500), add if (err instanceof QualLockedError) return sendError(res, 409, err.message); before the 500.
    • DELETE /api/tournaments/:id/qualifiers/:subId: before deleting, load the score row; if its runId points at a VERIFIED run, return 409 with the same message.
    • Roster removal: if the player's run is VERIFIED, return 409 with the same message (checked before the score-count check).
    • qualify/adjudicate: post the Discord VERIFIED message only when body.action === 'VERIFY' and the run was not already verified before the call (compare the status you loaded first).

B. formatQualTimestamp.ts (new)

const formatter = new Intl.DateTimeFormat(undefined, { dateStyle: 'medium', timeStyle: 'short' });

/** Full date and time for qual review, e.g. "Nov 1, 2026, 3:42 PM" in en-US. */
export function formatQualTimestamp(ms: number): string {
  return formatter.format(new Date(ms));
}
