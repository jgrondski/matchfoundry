Specs / Qual review / QR.1

Step QR.1: A qual is its own record

Move each competitor's qual (online or in-person, authword, VOD, Twitch, timer, notes, review status) out of the score rows into one qualifier_runs row, so a qual survives having zero scores.

Executor: any model. Prerequisite: none. Run before QR.2 and before Phase 12 step 12.2. Read first: index.html “Rules for every executor”, docs/TESTING_STRATEGY.md, and the “Database & Drizzle” section of CLAUDE.md.

Why

Today a qual exists only as its qualifier_submissions rows, and every row carries its own copy of the qual's details. Deleting the last score (Judge page player drawer, trash icon) deletes the qual: it vanishes from the Review page, and a score entered afterwards starts a brand-new in-person qual. Separately, EDIT_AND_VERIFY rewrites every row as ONLINE, turning in-person quals into online ones.

Behavior after this step: identical to today except (1) deleting every score leaves the qual in place with zero scores, (2) a score added later joins that qual and keeps its source and details, (3) editing an in-person qual's scores keeps it in-person, (4) reassigning a qual to a player who already has a qual in the tournament is refused.

B. src/api/qualRuns.ts (new)

Export exactly these. All take a resolved tournament UUID.

ExportBehavior
type QualRunRow = typeof qualifierRuns.$inferSelect

attachOrphanScoresToRuns(tournamentId): Promise<void>Backfill; see below. Idempotent and cheap when there is nothing to do (one select).

attachOrphanScoresToRuns algorithm

  1. Select all qualifier_submissions rows of the tournament where run_id IS NULL. If none, return.
  2. Group them by playerId. For each group, call a row a placeholder if its status is IN_PROGRESS or NOT_STARTED, otherwise scored.
  3. run = getRunForPlayer(...). If null, build one:
    • anchor = the first placeholder row if any, else the row with the latest createdAt.
    • submissionSource = 'ONLINE' if any row in the group is ONLINE, else 'IN_PERSON'.
    • status, first match wins: any placeholder → IN_PROGRESS; any DQ → DQ; any SUBMITTED → SUBMITTED; at least one scored row and all scored rows DNQ → DNQ; any VERIFIED → VERIFIED; otherwise SUBMITTED.
    • authWord, twitchVodUrl, submittedTwitchId, submittedTwitchUsername, identityStatus, timerLog, judgeNotes, playerNotes, verifiedBy, verifiedAt: from anchor. resumeToken and draft: from anchor if it is a placeholder, else null.
    • createdAt = earliest createdAt in the group.
    • submittedAt = null if status is IN_PROGRESS; else if ONLINE and anchor.timerLog?.submittedAt is set, new Date(anchor.timerLog.submittedAt); else the earliest createdAt among scored rows; else (no scored rows) the earliest createdAt in the group.
    • Insert it. If the insert fails because of qualifier_runs_tournament_player_idx (a concurrent backfill won), catch the error, re-select with getRunForPlayer and continue with that run. Any other error rethrows.
  4. Delete the group's placeholder rows.
  5. Set run_id = run.id on the group's scored rows.

Call sites (only these two): at the start of getFullTournament right after the tournament row is resolved, and at the end of resolveTournamentRow in qualifiers.ts before it returns. saveFullTournament needs no call because it ends with getFullTournament. This backfills production data lazily and also attaches rows inserted by the full-tournament save (simulation, legacy clients).
