Step 12.3: Compact bracket view

A new compact view that keeps the bracket's shape (rounds, connectors, champion) but shows only seed, name and match wins, so a whole bracket reads on a phone.

Executor: any model. Can run in parallel with 12.2 and 12.4. Prerequisite: 12.1 committed. Read first: index.html rules, 12.0's “Conventions”, and the conversion guide.

Design

AspectDecision
What a match showsTwo rows. Each row: seed (muted), name (truncated), match wins (for example 2, or 2 (t) with a tiebreaker). No game scores, no header strip, no routing chips.
Winner and loserThe winner row is bold, text-fg. The loser row is text-fg-muted and opacity-70. While in progress, the leading player's wins are text-gold-bright. Placeholders (“TBD”, “Winner of M#…”) are italic text-fg-muted with no seed.
GeometryUses the existing layout engine with a compact LayoutConfig, so pairing, bye and double-elim drop invariants come from the same code as the full view.
ScrollingThe bracket scrolls sideways inside its own container and snaps to round columns. Round headers stay visible while scrolling down.
Supported bracketsSingle elimination, and double elimination with traditional routing. Accelerated Hybrid and Flat Staged don't offer compact: the toggle is hidden and they fall back to the feed on mobile.
Tapping a matchThe same handler as the full view (onSelectMatch): judges get the score sheet, spectators get whatever the full view gives them today.
Default view on phonesPublic bracket pages: compact when supported, otherwise feed. Manage bracket pages: feed (judges score from the list). ?view= in the URL always wins. On desktop, compact is available from the toggle and is never the default.

Step 1: Layout

  1. In layout/types.ts: export type BracketViewMode = 'standard' | 'fit' | 'split' | 'feed' | 'compact'; and add: 
    export const COMPACT_LAYOUT_CONFIG: LayoutConfig = {
  matchWidth: 136,
  matchHeight: 44,
  baseRowHeight: 56,
  roundGap: 20,
  headerHeight: 36,
  paddingTop: 8,
  paddingLeft: 12,
  paddingRight: 16,
  paddingBottom: 16,
  championWidth: 140,
  championHeight: 44,
};
  2. In calculateBracketLayout, when viewMode === 'compact', merge COMPACT_LAYOUT_CONFIG under customConfig and call the same engine as 'standard' (pass 'standard' as the engine's view mode). Return viewMode: 'compact' in the metadata.
  3. Add and export supportsCompactView(bracket: BracketStructure): boolean. It returns false when bracket.bracketRouting === 'ACCELERATED_HYBRID' or when the bracket uses Flat Staged routing (reuse the exact check the visualizer uses to choose the flat staged layout; extract it into layout/index.ts if it's inline). Otherwise it returns true. Support both 'TRADITIONAL' and 'TRADITIONAL_TREE' (CLAUDE.md §3).

Step 2: Match card model

Move the per-match derivation in BracketMatchCard.tsx into matchCardModel.ts as a pure function. That covers effective player names, slot placeholders, p1Wins/p2Wins, hasTiebreaker, the score display strings, isComplete, inProgress, p1Won/p2Won, and the leading flags (currently around lines 120–225):

export interface MatchSideModel {
  name: string;          // effective name or placeholder text
  isPlaceholder: boolean;
  seed: number | null;
  winsDisplay: string;   // e.g. "2" or "2 (t)"
  won: boolean;
  leading: boolean;
}
export interface MatchCardModel {
  p1: MatchSideModel;
  p2: MatchSideModel;
  isComplete: boolean;
  inProgress: boolean;
  isPlayable: boolean;
}
export function getMatchCardModel(args: {
  match: BracketMatch;
  mIdx: number;
  bracket: BracketStructure;
  tier: TournamentTier;
  record: MatchScoreRecord | undefined;
}): MatchCardModel;

BracketMatchCard then calls getMatchCardModel and renders exactly as before. Existing bracket tests and visual screenshots must not change.

Step 3: CompactMatchCard.tsx

interface CompactMatchCardProps {
  model: MatchCardModel;
  pos: { x: number; y: number; width: number; height: number };
  accentColor: string;      // primaryColor, or lowerBracketColor for losers-bracket matches (same rule as BracketMatchCard)
  cardBg: string;           // effectiveCardBg
  matchDomId: string;       // `bracket-match-${match.id}`, so scroll-to-match keeps working
  onSelect?: () => void;    // undefined when the full view would not be clickable
}
  • Root: absolute flex flex-col overflow-hidden rounded-sm border border-line border-l-2, with runtime style={{ left: pos.x, top: pos.y, width: pos.width, height: pos.height, background: cardBg, borderLeftColor: accentColor }}. When onSelect is set: role="button", tabIndex={0}, Enter and Space call it, plus cursor-pointer.
  • Each row: flex h-1/2 items-center gap-1.5 px-1.5 text-2xs. Seed: w-4 shrink-0 text-right font-mono text-3xs text-fg-muted (empty for placeholders). Name: min-w-0 flex-1 truncate. Wins: shrink-0 font-mono font-bold. The row divider is border-t border-line-subtle on the second row.
  • Row state classes follow the Design table.
  • Tap target: the card is 44px tall (the row height set in the config). Don't add hover ancestry highlighting in compact mode.

Step 4: Wire it into the visualizer

  1. BracketCanvas: new prop compact?: boolean. When true, render CompactMatchCard for each match (building the model with getMatchCardModel) instead of BracketMatchCard. Pass onSelect only when BracketMatchCard's own click condition would allow a click (reuse that condition through the model's isPlayable and the same props). Connectors (BracketSvgConnectors) render unchanged from layout.paths, with a 1.5px stroke in compact mode. Round headers in compact mode: text-2xs font-bold uppercase tracking-wider, using the layout's header positions.
  2. BracketChampionNode: new prop compact?: boolean that renders a 44px-high card with a trophy icon (size 14) and the champion's name, truncated.
  3. BracketVisualizer: when effectiveObsView === 'compact', pass compact to BracketCanvas and BracketChampionNode. Hide the player-search highlight. Wrap the canvas in overflow-x-auto overscroll-x-contain snap-x snap-proximity. Render one zero-width snap-start marker per round header at left: header.x - 12. If the bracket doesn't support compact, treat compact as feed (the page handles this, see Step 5).
  4. BracketStageNavBar (double-elim stage jump bar): on mobile, its buttons scroll sideways (max-md:overflow-x-auto max-md:flex-nowrap).

Step 5: Page and toggle

  1. BracketTierBar: add a “Compact” chip to the view toggle (label “Bracket” on mobile, “Compact” on desktop). Show it only when supportsCompactView(activeTier.bracket). On mobile the toggle shows exactly List and Bracket.
  2. PublicTierBracketPage, in the localViewMode initializer: if urlView is set, use it. Else if OBS, use 'fit'. Else if window.innerWidth < 768: on manage routes use 'feed', on public routes use supportsCompactView(tier.bracket) ? 'compact' : 'feed'. Else use 'standard'.
  3. If localViewMode === 'compact' and the bracket doesn't support it, render the feed branch.
  4. Compact renders through the existing non-feed <main> branch with BracketVisualizer obsView="compact".

Step 6: Tests

  • compactBracket.test.ts:
    1. For generated single-elim brackets of 8, 13 and 16 players, and a double-elim bracket of 16, the compact layout has no two overlapping match rectangles, and every match position has width === 136 and height === 44.
    2. Byes never get a position (the match count equals N−1 for single elimination).
    3. supportsCompactView returns false for ACCELERATED_HYBRID, true for TRADITIONAL and TRADITIONAL_TREE.
    4. getMatchCardModel: a decided match marks exactly one side won; a tiebreaker produces "N (t)"; an empty slot produces isPlaceholder: true with seed null.
  • Visual: add bracket-compact (/${FIXTURE_SLUG}/${FIXTURE_TIER_SLUG}?view=compact) to PAGES for both projects. These are new baselines; the coordinator reviews and generates them.
  • Overflow: append public-bracket-compact with the same path.
