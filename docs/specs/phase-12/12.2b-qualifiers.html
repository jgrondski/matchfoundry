A. LeaderboardCardList.tsx

  1. In LeaderboardTable.tsx, the rows already come from deriveLeaderboard(tournament) filtered into filteredRows, and tier cutoffs are in cutoffRanks. Leave that as is. For each cell value the card shows (below) whose formatting is inline JSX in the table, extract that expression into an exported function in LeaderboardTable.tsx (for example formatPrimaryMetric(row, format), getVerifiedStatus(row)) and call it from both the table cell and the card. Rendering in the table must stay identical.
  2. Props: 
    interface LeaderboardCardListProps {
  rows: LeaderboardRankRow[];
  format: Tournament['qualFormat'];
  targetX: number;
  hasBrackets: boolean;
  cutoffRanks: Map<number, { tierName: string; color: string; count: number }>;
  isObsMode: boolean;
  onSelectRow: (row: LeaderboardRankRow) => void;
}
  3. LeaderboardTable renders <LeaderboardCardList … /> in place of the <table> (and its scroll wrapper) when useIsMobile() is true. The header, filter chips, empty-state text and PlayerDetailDrawer stay shared. onSelectRow does what the table row's onClick does (set the selected player and rank row); in OBS mode the cards are not buttons.
  4. Each row is an <li> with a Card padding="sm" containing a <button type="button" className="w-full text-left">. Tier-qualified rows get a left border in the tier color, as the table row does (border-l-4 with the runtime color as an inline style, using the same eslint-disable comment format the table uses).
Card lineContent (by qual format)
Line 1Rank (w-8 shrink-0 font-mono text-sm font-bold), flag and name (min-w-0 flex-1 truncate font-semibold), primary metric right-aligned (shrink-0 font-mono font-bold): AVERAGE_OF_X → average score; HIGH_SCORE → top score; POINTS → total points. Same values and formatting as the table cells.
Line 2Status badge (the same states as the Verified column), playstyle chip, and the bracket seed when hasBrackets. Wraps (flex flex-wrap gap-1.5).
Line 3AVERAGE_OF_X: the top-score chips. HIGH_SCORE: “Maxes 3 · Kicker 812,340” built from the same values as the two columns. POINTS: the points breakdown in its existing compact form.

Tier cutoff dividers render between cards, after the row whose rank is a key of cutoffRanks, as a full-width <li role="separator"> with the same text the table divider shows, in the tier color.

B. Record Qual Score on phones

The Button with data-testid="open-qualifier-entry" (around line 112) stays one element. Add max-md:fixed max-md:inset-x-3 max-md:bottom-[calc(4.25rem+env(safe-area-inset-bottom))] max-md:z-40 max-md:py-3 max-md:shadow-lg so it floats full width just above the admin bottom bar (see “Admin bottom bar clearance” in the conventions). When canManage, the component's root gets max-md:pb-20 so the button never covers the last card.

C. Entry and detail sheets

  • QualifierEntryModal.tsx: every score input gets inputMode="numeric" (if not already) and max-md:text-base. The submit/cancel footer uses the sticky sheet footer classes from the conventions with full-width buttons.
  • CreatablePlayerSelect.tsx: the dropdown list gets max-md:max-h-[40dvh] overflow-y-auto max-md:w-full; options get max-md:min-h-11; the input gets max-md:text-base.
  • PlayerDetailDrawer.tsx: sections stack; stat grids with 3 or more columns get max-md:grid-cols-2; any score input gets inputMode="numeric"; horizontal paddings above px-4 get max-md:px-4.
  • TournamentQualTimerHud.tsx: the compact variant fits in 328px: its row gets flex-wrap and text items min-w-0.
