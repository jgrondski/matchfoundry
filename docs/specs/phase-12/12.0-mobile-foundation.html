Step 12.0: Mobile foundation

The shared pieces every Phase 12 step builds on: phone presentation for overlays, back-gesture handling, touch-sized controls, and the mobile overflow test.

Executor: Claude (coordinator). Runs alone. Prerequisite: Phase 11 complete and committed. Read first: index.html rules and the conversion guide (it still governs every class choice).

Conventions for all of Phase 12

  • Mobile means below Tailwind's md breakpoint (768px). Phone-only styles use the max-md: variant layered on top of the existing desktop classes. Desktop classes are not rewritten.
  • Use useIsMobile() only when the structure differs (a table becomes a card list, or a sidebar becomes a menu). Use max-md: classes for everything else. In tests, useIsMobile() returns false, so existing desktop assertions keep working.
  • Targets: a 360×800 viewport has no page-level horizontal scroll; interactive controls in phone layouts are at least 44×44px; body text is at least text-xs.
  • Wide content that has to stay wide (the organizer sheet, the full bracket views) scrolls inside its own container (overflow-x-auto), never the page.
  • Visual tests: desktop screenshots must not change in any Phase 12 step. Mobile screenshots are expected to change; list them in the report, and the coordinator re-baselines them after review.

Part C: Back gesture and back button

Pressing the browser Back button or swiping back on a phone while an overlay is open should act like any other close attempt, and must not leave the page. Create src/components/overlay/useOverlayHistory.ts and call it from OverlayInner.

import { useEffect, useRef } from 'react';

const pendingBack = new Map<string, ReturnType<typeof setTimeout>>();

/**
 * Pushes a same-URL history entry while an overlay is open, so Back closes the overlay
 * instead of leaving the page. onBack returns true when the overlay is closing, or false
 * when it stays open (dirty prompt or busy); in that case the entry is pushed again.
 */
export function useOverlayHistory(id: string, isTop: () => boolean, onBack: () => boolean): void {
  const onBackRef = useRef(onBack);
  onBackRef.current = onBack;
  const closedByBack = useRef(false);

  useEffect(() => {
    const hrefAtOpen = window.location.href;
    const scheduled = pendingBack.get(id);
    if (scheduled) {
      // StrictMode remount: the previous entry is still in place.
      clearTimeout(scheduled);
      pendingBack.delete(id);
    } else {
      window.history.pushState({ ...window.history.state, overlay: id }, '');
    }

    const onPopState = () => {
      if (!isTop()) return;
      if (onBackRef.current()) {
        closedByBack.current = true;
      } else {
        window.history.pushState({ ...window.history.state, overlay: id }, '');
      }
    };
    window.addEventListener('popstate', onPopState);

    return () => {
      window.removeEventListener('popstate', onPopState);
      if (closedByBack.current) return;
      // Closed by a button, the backdrop or Escape: remove our entry, unless the app navigated away.
      pendingBack.set(
        id,
        setTimeout(() => {
          pendingBack.delete(id);
          if (window.location.href === hrefAtOpen && window.history.state?.overlay === id) {
            window.history.back();
          }
        }, 0)
      );
    };
  }, [id, isTop]);
}

In OverlayInner, add the reason 'back' to DismissReason and treat it like 'escape' in resolveDismissal (update the decision-table test to 32 cases). Then call:

useOverlayHistory(id, useCallback(() => isTopOverlay(id), [id]), () => {
  const result = resolveDismissal('back', { dirty, busy, dismissible });
  if (result === 'close') { onClose(); return true; }
  if (result === 'confirm') setConfirmOpen(true);
  return false;
});

React Router's BrowserRouter keeps working because the pushed entry carries the router's existing history.state (usr, key, idx) plus our overlay key, and the URL doesn't change.

Browser tests (add to e2e/overlays.spec.ts)

  2. Make it dirty, then page.goBack(). The Discard prompt appears, the drawer is still open, and the URL is unchanged. Click Keep Editing, then page.goBack() again: the prompt appears again.
  3. Close the drawer with its X, then page.goBack(). The browser goes to the previous page (no stale overlay entry left behind).
