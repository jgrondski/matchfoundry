Step 11.3: Cleanup and enforcement

Remove everything the migration left behind, turn on Tailwind's preflight, consolidate color data, and make the style rules permanent.

Executor: Claude (coordinator). Runs alone. Prerequisites: all ten 11.2 batches committed, and both waves reviewed. Read first: index.html rules and the conversion guide.

Step 1: Confirm the migration is complete

  1. npm run lint:styles -- src reports 0 errors. If any remain, list them by file and finish converting them using the guide before continuing.
  2. Collect the “arbitrary colors left for 11.3” lists from all ten batch reports (ask the user for them if they aren't in this conversation). Any value used in 2 or more places becomes a new @theme color token with a descriptive name; replace its arbitrary classes with the token. Values used once stay arbitrary.

Step 2: Palette module for color data

Create src/theme/palette.ts as the single home for hex values used as data.

  1. List every remaining hex literal: grep -rnoE "'#[0-9a-fA-F]{3,8}'" src --exclude-dir=__tests__. Exclude src/db/**; database column defaults are left alone (CLAUDE.md §3).
  2. Group them by meaning into exported constants in palette.ts:
    • DEFAULT_TIER_THEME: the default tier primaryColor/secondaryColor and the card/background/text defaults now repeated across tournament/defaults.ts, tournament/mock-data.ts, bracket/colorUtils.ts, server/api.ts.
    • DEFAULT_ORG_THEME and the org theme presets repeated across organizations/store.tsx, OrganizationDashboard.tsx, OrganizationDirectory.tsx, OrgBrandingTab.tsx, api/organizations.ts.
    • PLAYSTYLE_COLORS (from PlaystyleChip.tsx), ACCELERATED_HYBRID_POD_PALETTE (from routingChips.tsx), CHROMA_KEY_COLORS (OBS), and any status color maps.
  3. Replace every duplicate literal with an import of the constant. For constants that already exist and are exported elsewhere (for example ACCELERATED_HYBRID_POD_PALETTE), move them into palette.ts and re-export from the old module, so imports and tests keep working.
  4. Values must stay byte-identical. This step changes where colors live, never what they are. npm test must pass with no test edits.

Step 3: Remove legacy CSS

  1. For each class in the @layer components block of src/index.css (tabular-nums, animate-fade-in, animate-pulse-border, glass-panel, btn*, badge*, bracket-side-chip, top-nav-teleport-chip, qualifier-top-pods, qualifier-side-by-side-pods, obs-cards-grid), grep src for the class name used in a className. Delete the rule only when there are no matches. Note that tabular-nums, animate-fade-in and animate-pulse-border also exist as Tailwind utilities, so after deleting the legacy rules, those names keep working through the theme. Delete the empty @layer components block.
  2. For each legacy variable in the :root alias block (--color-bg-base … --radius-full), grep src for var(--that-name. Delete each alias with no matches. Replace any remaining match with the token name (var(--color-canvas) and so on) and then delete the alias. Delete the empty block.
  3. Keep the keyframes, select, .obs-overlay-mode and the @layer base rules.

Step 4: Enable preflight

Add @import 'tailwindcss/preflight.css' layer(base); between the theme and utilities imports. Then add these restoring rules at the end of the existing @layer base block, so that icons and headings keep their current rendering:

  /* Keep lucide icons inline, as they rendered before preflight. */
  svg { display: inline; vertical-align: baseline; }

Step 5: Make the rules permanent

  1. Move the styleRestrictions array from eslint.styles.config.js into eslint.config.js, then delete eslint.styles.config.js. Add a config block for src/**/*.{ts,tsx} (ignoring **/__tests__/**) with 'no-restricted-syntax': ['error', ...styleRestrictions, HEX_ANYWHERE], where HEX_ANYWHERE is { selector: "Literal[value=/^#[0-9a-fA-F]{3,8}$/]", message: 'Hex color literal. Use a theme token, or add it to src/theme/palette.ts.' }.
  2. Add an override block that turns HEX_ANYWHERE off for src/theme/palette.ts and src/db/**. ESLint can't remove a single selector, so the override re-declares no-restricted-syntax with only styleRestrictions.
  3. Remove the lint:styles script from package.json.
  4. Run npx eslint src and make sure it reports 0 errors. Warnings from existing rules such as no-explicit-any are fine; leave them alone.
