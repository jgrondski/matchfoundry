Tailwind Conversion Guide

The rules every 11.2 batch follows to turn inline styles into Tailwind classes and shared components. If two executors convert the same element using this guide, they should produce the same classes.

1. Principles

  1. Same look, same behavior. Small size and spacing shifts from snapping onto the scale are expected. Changed colors, missing borders, different wrapping or overflow, and changed layout are bugs.
  2. Static values become classes. A value is static if it is a literal, or a conditional choosing between literals.
  3. Runtime values stay inline. A value is runtime if it comes from props, state, data or a function call and can't be listed as a small fixed set. Examples: tier and org theme colors (primaryColor, cardColor, getAlternateShade(…)), layout engine coordinates (pos.x, pos.width), and font sizes passed in as props.
  4. Use shared components from src/components/ui wherever they fit (section 9).
  5. Never change text, element order, event handlers, ARIA attributes, data-testids, or exported names and props.

2. Per-file procedure

  1. Run npm run lint:styles -- <file> to list every violation.
  2. Work top to bottom. For each element, delete static properties from its style object and add the equivalent classes to className, using the tables below. Merge with an existing className, and use cn() once any part is conditional.
  3. If a style object ends up empty, delete the attribute. If only runtime values remain, keep it as an inline object literal holding only those values.
  4. Delete module-level CSSProperties constants (const overlayStyle: React.CSSProperties = …). Replace each with a const class string (const thClass = 'px-4 py-3 …';), or inline the classes when it's used once. style={someVariable} is not allowed. If the variable holds runtime values, spread it into an inline object literal.
  5. Replace hover workarounds (section 7).
  6. Replace legacy classes (section 8).
  7. Remove imports that are no longer used.
  8. Re-run npm run lint:styles -- <file> until it reports 0 errors.

3. Spacing and sizes

3a. Spacing: padding*, margin*, gap, rowGap, columnGap, top/right/bottom/left, inset

Convert to px (1rem = 16px). Divide by 4, then round to the nearest multiple of 0.5; ties round up. Use that as the class step. 0 → -0; 1px → -px; auto → -auto.

Theme data is not a style. Hex values used as data stay exactly where they are. That covers object values for keys like primaryColor, secondaryColor, cardColor, backgroundColor, textColor, lowerBracketColor, palette maps, defaults, and arguments to color helpers such as getAlternateShade/colorWithAlpha. 11.3 consolidates them into a palette module. The lint rule only flags hex values inside style attributes.

5c. rgba() and alpha

Express the color in RGB, find it as a token or palette color, and use the alpha as an integer percent: rgba(255,255,255,0.05) → white/5; rgba(0,0,0,0.4) → black/40; rgba(245,158,11,0.15) → gold/15; rgba(239,68,68,0.3) → red/30; rgba(148,163,184,0.1) → slate-400/10; rgba(16,185,129,0.12) → green/12; rgba(255,201,5,0.08) → tier-gold/8. Round the percent to the nearest integer. RGB values that are neither a token nor a palette color → arbitrary bg-[rgba(11,14,20,0.94)], listed in the report.

Runtime color strings built from data, such as `${tierColor}40` or colorWithAlpha(primaryColor, 0.2), stay inline.

7. Hover, focus and pressed workarounds

  • Handlers that only mutate the element's own style (e.currentTarget.style.background = …) → delete both handlers and add hover: classes with the same values. If the handler mirrors a focus state, use focus-visible:.
  • Handlers that set React state used elsewhere (for example setHoveredMatchId) stay. Only the style mutations inside them go.
  • A hover color that is a runtime value: set it as a CSS variable inline and reference it in a class. style={{ '--row-hover': hoverTint }} plus hover:bg-(--row-hover).
  • A parent hover that styles a child → group on the parent and group-hover: on the child.

Don't create new shared components in a batch. If a pattern repeats 5 or more times in your batch and none of these fit, note it in the report.

10. Allowed exceptions

When a rule can't be satisfied without changing behavior, add // eslint-disable-next-line no-restricted-syntax -- runtime: <reason> on the line above, and list it in the report. Valid reasons: a style object assembled in a helper and returned to the caller (for example the bracket canvas positioning), or a third-party component that only accepts a style prop. “Too many classes” is not a valid reason.

11. Tests

  • Change a test only when it asserts rendered inline styles from a file in your batch. The batch file lists these. Rewrite the assertion to check the equivalent class (for example toContain('rounded-full')) and keep the intent of the test.
  • Tests that check data returned by helpers (for example routingChips colors) must not change.
  • Never delete or skip a test.
