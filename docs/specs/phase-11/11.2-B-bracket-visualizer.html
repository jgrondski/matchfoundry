Batch-specific notes

  • Card and canvas geometry comes from the layout engine (pos.x, pos.y, pos.width, pos.height, connector paths), and font sizes are passed as props (nameFontSize, seedDim, …). All of these are runtime and stay inline.
  • Tier and theme colors (primaryColor, secondaryColor, textColor, effectiveCardBg, lowerBracketColor) are runtime. Where they drive hover or active states, pass them as CSS variables (guide §7).
  • BracketTierBar.tsx: convert the tier buttons to <Chip accent> and the view-mode toggle buttons to <Chip size="sm">. The sticky top depends on viewMode/canManage: use conditional classes top-0 / top-14. Keep the ResizeObserver that sets --bracket-tier-bar-height exactly as is.
  • BracketMatchCard.tsx: animation: isFocusedMatch ? 'matchZoomPulse 2.4s ease-in-out' : undefined → isFocusedMatch && 'animate-match-zoom-pulse'. It also has hover handlers (guide §7).
  • BracketQualifierPodGrid.tsx: qualifier-top-pods / qualifier-side-by-side-pods → guide §8.
  • routingChips.tsx returns color data that tests assert on. Change only its JSX (one style site); leave the returned objects and palette constants alone.
  • BracketThemeEditor.tsx holds color-picker data: hex values used as data stay put (guide §5b box).
